# WP-GOV-01C Implementation Report (Evidence Synthesis Engine)

## 1. Exact Implementation Scope
Implementation of the Evidence Synthesis Engine strictly as defined by the `wp-gov-01-engineering-specification.md` and constrained by the `wp-gov-01c-architecture-authorization-review.md`. The engine translates flat `EvidenceProjection` records generated by WP-GOV-01B into a relational Traceability Graph represented by `TraceabilityNode` and `TraceabilityEdge` records.

## 2. Architecture Used
- **Synchronous Integration:** The synthesis trigger is integrated directly at the end of the atomic projection transaction in `ingestion-adapter.ts`.
- **Pure Governance Plane:** Synthesis occurs entirely within the `governance` schema.
- **Idempotent Upsertion:** The graph topology is strictly recomputed from existing projections without duplication.

## 3. Input Contract
- **Source Data:** `governance.EvidenceProjection` (derived by WP-GOV-01B).
- **Provisions:** Active rules from `governance.Provision`.
- **Boundaries:** All identity resolutions (`assignment_id` to `submission_id`) have already been performed by WP-GOV-01B via the certified resolver. No Publication-plane RPCs or schemas are queried.

## 4. Synthesis Algorithm
1. Retrieve all `EvidenceProjection` records sharing a `submissionId` in their state payload.
2. Group evidence by `entityType` (Submission, Review, Decision).
3. Upsert a `SUBMISSION` TraceabilityNode and connect it to all active `PROVISION` nodes via `REQUIRES` edges.
4. Upsert `REVIEW` TraceabilityNodes and connect them to the `SUBMISSION` node via `EVIDENCES` edges.
5. Upsert `DECISION` TraceabilityNodes, sorted by `updatedAt` to establish logical time. Create `DECIDES` edges to the submission and `SUPERSEDES` edges from newer decisions to older ones.

## 5. Output Model
Outputs strictly map to pre-existing models established by WP-GOV-01A:
- `governance.TraceabilityNode` (storing type, label, and stringified minimal state).
- `governance.TraceabilityEdge` (storing directional relationships like `EVIDENCES`, `DECIDES`, `REQUIRES`, `SUPERSEDES`).

## 6. Provenance Model
- Nodes retain their direct linkage to their root source identifier via `metadata.sourceId`.
- Edges preserve strict structural correlation (e.g., this `REVIEW` provides evidence for this exact `SUBMISSION`).
- No raw sensitive payloads are stored; only the minimized state provided by the underlying projection is embedded in node metadata.

## 7. Determinism Model
- **Idempotency:** Using `upsert` and `findFirst` ensures that repeated processing of the same evidence set yields the exact same nodes and edges.
- **Graph Hashing:** `computeTraceabilityGraphHash` sorts nodes and edges lexicographically by ID before serializing, guaranteeing the same subgraph topology produces the same SHA-256 hash.
- **Time/Ordering:** Conflict resolution (e.g., superseding decisions) uses deterministic logical timestamp sorting.

## 8. Concurrency Model
- The synthesis algorithm executes synchronously inside the same PostgreSQL transaction used by the ingestion adapter (`withIngestRole(async tx => ...)`).
- This ensures atomic projection and synthesis, relying on row-level locks on the parent `EventReceipt` and `EvidenceProjection` to serialize concurrent attempts.

## 9. Security Model
- Uses the certified `governance_ingest_role` which operates purely inside the `governance` schema.
- Does NOT execute any SECURITY DEFINER functions.
- Has absolutely ZERO read or write access to the Publication plane (`public.*`).

## 14. Known Limitations
- The engine computes a complete subgraph but WP-GOV-01D (the evaluator) is not yet implemented to consume the hash or graph for certification.
- Node UUIDs use random CUIDs/UUIDs unless tied strictly to the projection ID. Currently edge IDs are generated per run, meaning the internal primary key changes on UPSERTs, but the deterministic hash relies on topological mapping. (We enforced edge ID stability by only creating if missing).

## 15. Unresolved Architectural Questions
- Confidence / Quality scoring heuristics were unspecified and thus omitted. WP-GOV-01D will need to evaluate the raw state to determine policy adherence.
- Should node hashes be cached? We opted for dynamic subgraph hashing as needed.
